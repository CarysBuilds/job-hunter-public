# Job Hunter 使用说明

Job Hunter 是一个在本机运行的求职助手，可以从 BOSS 直聘、猎聘和智联招聘抓取岗位，按照你的求职偏好进行匹配评分，并记录岗位和投递进度。

它不会自动投递，也不会自动给招聘者发消息。所有抓取操作都需要你手动启动。

## 下载与安装

使用前请先安装 [Google Chrome](https://www.google.com/chrome/)。Job Hunter 会打开独立的 Chrome 窗口供你登录招聘平台和抓取岗位，不会使用你平时的 Chrome 登录状态。

前往 [GitHub Releases](https://github.com/CarysBuilds/job-hunter-public/releases/latest)，按电脑系统下载对应的安装包：

- Windows 10/11 x64：下载 `JobHunter-Setup-x64.exe`，双击安装后从桌面或开始菜单打开。
- macOS（Apple 芯片与 Intel 通用）：下载 `JobHunter-macOS-Universal-v0.2.0.dmg`，打开后把 `Job Hunter` 拖入“应用程序”。

页面中的 `Source code (zip)` 和 `Source code (tar.gz)` 是供开发者使用的源码包，普通用户无需下载。

安装并启动 Job Hunter 后，操作界面通常会在默认浏览器中自动打开。如果没有自动打开，请保持 Job Hunter 正在运行，并访问 [http://127.0.0.1:17321](http://127.0.0.1:17321)。这个地址只在当前电脑本机可用。

Windows 可能因为安装包尚未获得商业代码签名而显示“Windows 已保护你的电脑”或其他安全提醒。这不代表程序一定有问题。请确认安装包来自本项目的 GitHub Releases 页面，然后点击“更多信息”→“仍要运行”继续安装。如果安装包来自网盘、群聊或其他不明来源，请不要直接运行。

macOS 安装包目前尚未经过 Apple 公证。首次打开若提示无法验证开发者，请确认文件来自本项目的 GitHub Releases 页面，然后在 Finder 中右键 `Job Hunter` 并选择“打开”。详细步骤见 [macOS 安装说明](docs/macos-install.md)。Windows 的详细步骤见 [Windows 安装说明](docs/windows-install.md)。

## 工作台

- “今日行动”：待沟通、到期跟进、待投递、面试中四个队列。
- “全部岗位”：筛选、排序并查看评分证据。
- “我的资料”：管理画像、简历与屏蔽规则。
- “更多”：查看来源健康、任务诊断，以及导出岗位或沟通记录。

## 第一次使用

首次打开后，先进入“设置”填写以下内容：

- 抓取关键词：你想找的岗位名称，例如“产品经理”“Java 开发”“新媒体运营”。系统会按照每个关键词分别在招聘平台搜索。
- 目标方向：用于判断抓取到的岗位是否符合你的求职方向，只影响匹配评分，不会代替抓取关键词。
- 抓取城市：直接填写城市名称，例如“北京”。如果同时找多个城市，用逗号分隔，例如“北京,上海,杭州”，最多填写 5 个。系统会自动转换成三个平台各自使用的城市参数，转换规则见 [城市匹配说明](docs/city-codes.md)。
- 经验、期望薪资和偏好城市：用于岗位评分和排序，不会修改招聘平台上的个人资料。
- 简历内容：用于岗位能力匹配和生成打招呼草稿，只保存在本机数据目录中。
- 模型 API Key：用于更准确地比较简历与岗位要求，也用于生成打招呼草稿。不填写时使用本地文字重合匹配，不会把简历发送到外部服务。

简单理解：

- “抓取关键词”决定搜什么。
- “目标方向、经验、薪资和城市偏好”决定抓取结果如何评分和排序。

## 登录三个招聘平台

抓取前需要分别登录 BOSS 直聘、猎聘和智联招聘账号：

1. 点击“打开 BOSS 登录”，在打开的 Chrome 中完成登录。
2. 点击“打开猎聘登录”，在另一个 Chrome 中完成登录。
3. 点击“打开智联登录”，在第三个 Chrome 中完成登录。

三个平台会使用三个独立的 Chrome 浏览器窗口和本地登录目录。启动和抓取期间请保持对应的 Chrome 窗口打开，不要退出浏览器或关闭登录页面所在的窗口。

应用会在每次抓取前检查对应平台的登录状态。未登录或登录失效时，会提示先完成登录，不会直接开始抓取。

这些 Chrome 窗口与平时使用的 Chrome 登录环境相互独立，因此即使你平时已经在招聘网站登录，也可能仍需在 Job Hunter 打开的窗口中重新登录一次。

## 抓取岗位

完成设置和登录后，点击“抓取 BOSS”“抓取猎聘”或“抓取智联”。

为了降低访问频率、减少触发平台风控的概率，自动抓取会在页面操作之间主动等待。关键词越多、抓取页面越多，总耗时越长。长时间停留在“正在抓取”通常不是卡死，请保留应用和对应的 Chrome 窗口，等待任务完成。

三个平台需要分别点击抓取，当前不会一次同时抓取全部平台。岗位是按照设置中的关键词逐个搜索的；如果关键词过多或过于宽泛，抓取时间和结果数量都会增加。

## 遇到登录验证或平台风控

招聘平台可能因为访问频率、登录环境变化或账号状态触发短信验证、滑块验证、安全验证或临时限制。

遇到此类情况时：

1. 立即停止重复点击抓取。
2. 回到对应的 Chrome 窗口，查看是否需要人工完成验证。
3. 如果仍然无法使用，关闭本次操作并等待一段时间后再登录和抓取。
4. 不要在短时间内反复刷新、重新登录或连续启动抓取，这可能延长限制时间。

平台风控由招聘网站决定，Job Hunter 无法绕过，也不能保证每次抓取都成功。

## 岗位评分与猎头岗位

系统使用通用评分 v7：方向 30、简历能力 25、门槛 15、条件 15、JD 质量 15，风险扣分为 0 到 -30。最终分与面试匹配分相同；公司质量独立展示，只在岗位同分时用于排序。评分只用于辅助筛选，不代表岗位一定适合或一定能获得面试，请在投递前阅读完整职位描述。

公司类型、规模、融资阶段、作息和福利会作为事实信号展示。外包与作息默认只提示，不自动扣岗位分。销售风险会结合目标方向和用户填写的风险容忍度判断；疑似拉人头、虚假高薪、快速开单与电话/微信成交的组合信号会强制标为 D。

“匹配能力”只依据用户上传的简历：

- 未上传简历时，能力维度为 0 分，并显示“需上传简历后进行能力匹配”。
- 已上传简历但未配置模型 API 时，只在本机查找简历与 JD 中直接重合的能力词，不推断隐含能力或能力差距。
- 已上传简历并配置模型 API 时，会把简历和岗位描述发送到用户配置的模型服务，由模型根据双方证据返回匹配能力、明确差距和 0–25 分能力分。

上传或修改简历后，请点击“重新评分”，已有岗位才会使用最新简历重新计算。

详细匹配方式和模型提示词原则见 [简历与岗位能力匹配](docs/resume-matching.md)。

识别为猎头或招聘顾问发布的岗位最高为 C 级；若同时命中更强风险，仍可能是 D 级。岗位会保留在列表中，方便你自行判断。

如果修改了目标方向、经验或薪资等设置，可以点击“重新评分”，无需重新抓取岗位。

## 生成打招呼草稿

使用前需要同时满足两个条件：

1. 在“设置”中上传或粘贴至少 80 个字符的简历内容。
2. 填写可用的模型 API Key、API Base 和模型名称。

打开岗位详情后点击“生成打招呼草稿”。系统只会生成文案草稿，不会自动发送给招聘者。生成时，简历内容和当前岗位描述会发送到你配置的模型 API，请根据所使用模型服务商的隐私政策自行判断是否启用。

草稿保存前会扫描电话、邮箱、年龄、微信/QQ、证件、银行卡和网址；命中或扫描异常时不会保存。JD 会按不可信文本处理，避免其中的提示词指令影响生成。复制并手动发送后，可点击“登记已沟通”。

## 数据保存与更新

岗位、设置、简历和登录状态保存在独立的用户数据目录中。安装新版或删除应用程序本身不会自动删除这些数据。程序在数据库升级和全量删除前会自动创建并校验备份；请勿在 Job Hunter 运行时手动移动或修改数据文件。

## 常见问题

### 为什么点击抓取后没有立即出现岗位？

系统会先检查登录状态，再按关键词逐页抓取，并在操作之间等待。请观察顶部状态提示，不要连续点击抓取按钮。

### 为什么已经在 Chrome 登录，应用仍提示未登录？

Job Hunter 为三个平台分别使用独立的 Chrome 用户目录。请使用应用通过“打开 XX 登录”启动的对应浏览器窗口完成登录。

### 可以关闭三个 Chrome 窗口吗？

不抓取时可以关闭。开始抓取前需要重新打开对应平台窗口并确认登录状态；抓取过程中不要关闭。

### 关键词应该怎么填？

填写招聘网站中常见的岗位名称，并用逗号分隔。例如：

```text
产品经理,产品运营,用户运营
```

建议先使用 1～3 个准确关键词测试。关键词太宽泛会带来大量不相关岗位，关键词太具体则可能没有结果。

### 抓取城市和偏好城市有什么区别？

抓取城市用于招聘平台搜索；偏好城市用于本地评分。只填写偏好城市不会自动改变平台的搜索城市。填写多个抓取城市后，系统会按照“每个关键词 × 每个城市”依次搜索，因此城市越多，总耗时越长。平台参数的转换规则见 [城市匹配说明](docs/city-codes.md)。

### 为什么同一个岗位会出现多次？

同一职位可能由不同平台、不同发布者或不同链接发布。系统会去除内容完全相同的重复数据，但会保留来源、薪资、地点或职位描述不同的记录。

### 为什么有些岗位信息不完整？

招聘平台列表页展示的信息有限，详情页也可能需要登录、验证或已经下线。系统会尽量保留可读取的内容，不完整信息会影响评分准确度。

### API Key 是 Job Hunter 提供的吗？

不是。API Key 需要向你选择的模型服务商申请，使用费用和额度也由该服务商收取。仅抓取和查看岗位不需要 API Key。

## 本地数据与隐私

- Windows 安装版的数据目录是 `%APPDATA%\JobHunter\data`。通常对应 `C:\Users\你的用户名\AppData\Roaming\JobHunter\data`。可按 `Win + R`，粘贴 `%APPDATA%\JobHunter\data` 后回车直接打开。
- macOS 安装版的数据目录是 `~/Library/Application Support/JobHunter/data`。在 Finder 中选择“前往”→“前往文件夹”，粘贴该路径即可打开。
- 数据目录包含岗位数据库、设置、简历、日志和三个平台的独立 Chrome 登录目录。
- 应用不会导出招聘平台 Cookie。
- 只有手动点击抓取后，应用才会访问对应招聘平台。
- 本地服务默认只允许本机访问。
- 配置模型 API 后，岗位评分和打招呼草稿会把简历及对应岗位描述发送到你自行配置的模型服务；未配置 API 时能力匹配完全在本机进行。
- 卸载或删除应用会保留用户数据。如需彻底删除，请先关闭 Job Hunter 和它打开的三个 Chrome 窗口，再删除对应系统的数据目录。

更多信息见 [隐私说明](docs/privacy.md) 和 [平台访问说明](docs/platform-policy.md)。

## 使用提醒

请合理控制抓取频率，并遵守招聘平台的用户协议和适用法律。招聘网站页面结构或登录规则发生变化后，部分功能可能暂时失效，请以项目后续版本为准。
